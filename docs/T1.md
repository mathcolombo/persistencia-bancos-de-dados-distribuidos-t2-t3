# T1 — Escolha e modelagem

Objetivo: executar SQL e um cliente parametrizado; comparar os seis modelos e justificar duas decisões.

## 1. Preparar a massa

```text
python lab.py up basic
python lab.py sql basic -f sql/sanity.sql
```

Contagens: cliente 2; produto 3; estoque 3; pedido 2; item_pedido 4. O bloco de sanidade captura violações esperadas em subtransações e deixa a massa intacta. Para demonstrar explicitamente `BEGIN`/`ROLLBACK`, entre no psql:

```text
docker compose exec basic psql -U postgres -d horizonte
```

Digite uma linha de cada vez:

```sql
BEGIN;
INSERT INTO item_pedido VALUES(701,30,0,50);
ROLLBACK;
BEGIN;
INSERT INTO pedido VALUES(999,999,'CRIADO',1);
ROLLBACK;
```

O primeiro INSERT deve falhar pelo CHECK de quantidade; o segundo pela chave estrangeira do cliente. Guarde as mensagens e saia com `\q`. Não usar `ON CONFLICT` para esconder as falhas esperadas.

## 2. Completar as consultas

Edite `sql/03_consultas.sql` nos pontos indicados. A consulta de pedidos precisa reunir pedido, cliente e itens e usar o preço **histórico** do item. Resultados: pedido 701 = 260,00 e pedido 702 = 195,00. Usar o preço atual da mochila produziria 200,00 para o segundo pedido e violaria o requisito.

```text
python lab.py sql basic -f sql/03_consultas.sql
```

No catálogo, TRILHA entre 80 e 120 deve retornar produto 10; entre 40 e 60 deve retornar produto 30. Os limites são inclusivos.

## 3. Completar o cliente

Escolha `exercicios/respostas.py` → `catalogo_sql` **ou** `exercicios/Respostas.java` → `catalogoSql`. O cliente já recebe e valida parâmetros, abre e fecha a conexão; falta a consulta parametrizada. Python usa `%s`; JDBC usa `?`. A ordem é categoria, mínimo e máximo. Não adicionar aspas ao placeholder nem interpolar entrada no SQL.

Python:

```text
python lab.py client python catalogo TRILHA 80 120
python lab.py client python catalogo TRILHA 40 60
python lab.py client python catalogo TRILHA 500 600
python lab.py client python catalogo TRILHA 120 80
```

Java:

```text
python lab.py client java catalogo TRILHA 80 120
python lab.py client java catalogo TRILHA 40 60
python lab.py client java catalogo TRILHA 500 600
python lab.py client java catalogo TRILHA 120 80
```

Esperado: produto 10; produto 30; lista vazia; erro legível de faixa inválida. O último comando retorna código diferente de zero de propósito.

## 4. Interpretar e justificar

Use `docs/interpretacoes_T1.md`, com dados, consultas e resultados fornecidos para documentos, chave-valor, grafos, séries temporais e vetores. Não instalar MongoDB, Redis, Neo4j ou pgvector para esses itens.

Preencha `modelos/matriz.csv` e duas cópias de `modelos/ADR.md`. Os arquivos de interpretação apresentam resultados didáticos fornecidos; identifique-os como tal. Anexe a contribuição individual e o relatório de até quatro páginas conforme o enunciado.

## 5. Conferência

```text
python lab.py test t1 --linguagem python
```

Troque `python` por `java` após `--linguagem` se essa foi sua escolha. O teste verifica a massa, a execução das consultas, os casos do cliente e a rejeição de faixa inválida. Ele não avalia automaticamente a qualidade da matriz nem das ADRs.
